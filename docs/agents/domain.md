# Domain documentation

This is a single-context repository. Read `CONTEXT.md` and relevant decisions in `docs/adr/` before exploring or changing domain behavior.

Use the glossary's vocabulary in code, specifications, and issue titles. If a proposed change conflicts with an ADR, identify the conflict explicitly before changing that decision.

Missing domain documents do not block exploration. The domain-modeling workflow adds them when a real term or decision needs recording. Do not create a multi-context layout unless the repository grows into distinct bounded contexts.
